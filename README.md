# GovStatScope AI Orchestrator

> **Public live deployment coming soon!**

GovStatScope is a stateful multi-agent orchestration platform built to query, normalize, and synthesize government statistical data. It leverages an autonomous AI workflow to route natural language queries to the appropriate statistical agency (GUS BDL for Poland, FRED for the US), construct accurate API requests, and perform comparative data analysis.

## Architecture & Tech Stack

- **Frontend**: React 18, TypeScript, Vite, TailwindCSS — served via S3 + CloudFront
- **Backend Core**: Python 3.12, Async FastAPI on AWS Lambda (Lambda Web Adapter, response streaming for SSE)
- **AI Orchestration**: LangGraph (Stateful Multi-Agent Workflow: Router → API Engineer → Analyst)
- **LLM Provider**: Dynamic multi-provider support enforcing strict JSON schemas:
  - Production: Amazon Bedrock (Nova Lite via EU inference profile, cost-gated by a DynamoDB daily quota guard)
  - Development/Local: OpenAI-compatible endpoints (LM Studio, Ollama, vLLM, LiteLLM)
- **External Data Adapters**: Asynchronous clients for GUS (Bank Danych Lokalnych) and US FRED APIs, normalizing payloads into shared internal schemas
- **Infrastructure (AWS, CDK-defined in `infra/stack.py`)**:
  - AWS Lambda (single container-less Python function, `RESPONSE_STREAM` invoke mode)
  - CloudFront (static frontend hosting + `/api/*` proxy to Lambda Function URL)
  - DynamoDB on-demand tables:
    - `govdata-sessions-v2` — LangGraph session state & checkpointing (TTL enabled)
    - `govdata-llm-quota` — atomic daily LLM request counters per scope (TTL enabled)
    - `govstat-gus-cache` — GUS API response caching (TTL enabled)
  - IAM: least-privilege roles generated by CDK, scoped to exactly these tables + Bedrock invoke

## Local Development Setup

1. **Configure Environment Variables**:
   Copy the example environment file and populate it with your API keys.

```bash
cp .env.example .env
# Edit .env to include AWS credentials, GUS API key, FRED API key, and LLM settings
```

2. **Run via Docker Compose**:
Spins up the FastAPI backend, React frontend, and local DynamoDB instance.
```bash
docker compose up --build
```

3. **Deploy to AWS** (Lambda + CloudFront + DynamoDB):
```bash
cd infra
cdk bootstrap   # first time only
cdk deploy
```

4. **Access the Application**:
* Local Frontend UI: `http://localhost:3000`
* Local Backend API Docs: `http://localhost:8000/docs`
* Production URL: CloudFront domain emitted as `CloudFrontDomainName` stack output

## Testing

All test suites run via the repository PowerShell harness:

```powershell
.\scripts\test.ps1 -TestType unit         # unit tests
.\scripts\test.ps1 -TestType integration # integration tests (mocked fixtures, local DynamoDB)
.\scripts\test.ps1 -TestType all         # full suite
```
